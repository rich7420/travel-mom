# 旅行社工作流程涵蓋度核對

核對日期：2026 年 10 月 3 日。依據：目前媽媽介面、API、服務、資料表與既有回歸驗證。工作假設：媽媽主要處理散客／親子旅客的機票與飯店詢問；尚未量測她各類工作的比例，因此不提供涵蓋率百分比。

**目前涵蓋機票／飯店售前主流程的一部分，不能宣稱已涵蓋旅行社大部分完整任務。** 能走通的是「建立需求 → 保存查價條件或人工錄入供應商方案 → 比較與選案 → 編輯並複製客戶回覆」。成交後的期限、金流、訂購證據、文件交付與異動處理仍有明確缺口。

「可使用」表示媽媽可以在網頁完成該項；「部分」表示只能記錄或整理其中一段；「待建」表示沒有可完成、可追溯的工作流程。功能存在不等於真實供應商或正式部署已驗證。

| --- | --- | --- |
| 接待詢問、確認需求 | 可使用 | 逐題收目的地、日期、人數與預算；可接續、修改及搜尋案件。完整旅客名冊與長期客戶聯絡歷史仍未建立。 |
| 旅客組成與需求修改 | 可使用 | 成人、小孩、嬰兒、年齡；日期／人數修改會讓舊方案失效。不是護照／英文姓名／特殊服務需求的完整旅客管理。 |

| 方案比較與選取 | 可使用 | 機票、飯店各選一個；保留人工方案歷史、查詢時間與有效期限，阻擋示範／過期／需求變更方案；幣別分開。尚非多套套餐與多航段組合管理。 |

| 訂金、尾款、供應商付款與對帳 | 待建 | 沒有收付款帳、付款狀態核對、收據或毛利計算；仍用公司既有系統。最終付款保留人工，不妨礙日後增加帳務紀錄。 |

| 行前資料與交付 | 待建 | 「準備行前資料」只是提示接回案件，沒有缺件清單、電子機票／住宿憑證彙整、行前包產出與交付確認。 |

## 核對的具體證據

- 媽媽入口：`app/mom_static/app.js` 的建立、修改、查價、人工方案、選取與草稿操作。`runIntentAction` 的行程／簽證只有提示；行前下一步回到案件。
- `app/workflow_models.py` 的人工方案種類只有機票與飯店；`app/services/case_workflow.py` 與 `app/workflow_repository.py` 保存方案、案件快照與選取。這些資料不是已訂購證據。
- `app/services/replies.py`／`case_workflow.py` 提供固定格式草稿；有選案時金額保持確定性，不依賴 AI 自由計算。草稿編輯不會自動保存成正式報價或完整訊息歷史。
- `app/services/mom_ux.py` 的首頁按出發日與狀態排序，`priority` 最多四筆；`app/services/radar.py` 提示即將出發與待核准，沒有任務到期排程。
- `app/main.py` 的重新驗價與 preflight 是管理介面／API 能力。`app/services/policy.py` 的 BOOK／TICKET／CANCEL／REFUND 是授權規則；`approval_repo` 保存核准，不會替代交易執行。
- `app/db.py` 與實際 SQLite schema 有案件、查價、方案／選取、核准、稽核及偏好；沒有正式報價版本、待辦期限、訂購確認、收付款、文件附件或行前交付資料表。

## 下一包最有幫助的修改

1. **報價版本與客人決定**：一案多版、包含／不含項目、對客價格與內部成本分離、有效期限、客人接受哪版。驗收：三版可追溯；變更不覆蓋已送出內容。
2. **期限待辦與追蹤**：何時回覆、催客人、訂金／尾款、開票、免費取消與行前交付；有責任人、來源與完成紀錄。驗收：所有未完成到期任務可見，完成後停止提醒，不只顯示四個案件。
3. **訂購確認與行前交付**：人工錄入確認號／票號、核對確認單、收付款紀錄、文件缺件與交付清單。驗收：沒有正式證據不能當成確認完成；行前缺件清楚列出。

之後再補改退／旅中異常、CRM／交接與媽媽常賣的其他旅遊產品。OpenClaw 可在未來擔任選配查詢執行器，登入後的使用介面仍是網頁；接上它不會自動補齊上述業務紀錄。

## 本次重新驗證

136 個測試在 Python 3.12 與 3.11.14 均通過，包含案例修改、過期／變更方案、跨幣別、引導接單、固定格式草稿與 Access 權限。完整 Chrome 操作回歸再次通過：連續三位客人、旅客帶入、保存需求、人工機票／飯店方案、選取、編輯與複製草稿、重新載入保留選案。這些使用本機合成案例，證明操作與資料處理，不代表即時價格或正式交易已驗證。
