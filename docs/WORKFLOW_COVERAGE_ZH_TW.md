# 旅行社工作流程涵蓋度核對

核對日期：2026 年 10 月 3 日。依據：媽媽介面、API、服務、schema 804 與本機回歸。工作假設：媽媽主要處理散客／親子旅客的機票與飯店；尚未量測各類工作比例，不提供涵蓋率百分比。

**目前可走通機票／飯店的人工工作主線：接單 → 查價與選案 → 報價與客人採用 → 訂購確認／收付款 → 文件核對 → 行前交付 → 業務結案／重新開案。** 工具保存業務證據與下一步，供應商查價、訂購、開票、收付執行、傳訊息與原始文件交付仍由媽媽或公司既有系統處理。能記錄完整主線，不等於已涵蓋所有旅行社任務。

「可使用」表示網頁可完成所述紀錄／整理；「部分」表示仍缺專門產品或執行能力；「待建」表示沒有完整專門流程。功能存在不等於正式交易或公開部署已驗證。

## 驗收與證據

- schema 803 新增七張業務資料表，升級 802 兩次不遺失案件／方案。版本、紀錄修正、稽核與重試結果使用同一寫入交易。
- 有理由的報價異動保留款項；有效訂購確認可重新核對沿用，文件關聯／必備標示可有理由修正，避免缺件永久卡住。
- 分幣別、金額精度、退款上限、不完整成本、跨案件關聯、重複提交／並發、變更與失效、公開文件私有欄位隔離均有測試。
- 以真正 RSA 簽章測試 Access operator 操作整條業務流程、文件輸出與未知路徑／錯誤方法／跨來源／未登入拒絕。這是測試環境，沒有公開 tunnel 或 IdP 驗證。
- Chrome 實際操作報價、明確送出／採用、待辦完成、訂金、訂購確認、缺件草稿、備妥摘要、人工交付及變更失效，並檢查額外大字與手機、登入後續接原表單。既有接單／選案／一般回覆與網頁指南也持續回歸。

原業務流程驗證見 [業務流程實作驗證](AGENCY_OPERATIONS_VERIFICATION.md)；最新結案、三種瀏覽器與還原結果見 [結案與備份還原驗證](LIFECYCLE_RECOVERY_VERIFICATION.md)。資料使用合成案例；沒有對外發訊、收付款、真實出票訂房或媽媽工作量量測。

## 接下來的修改方向

1. **原始文件與旅客名冊**：受控附件、每位旅客文件欄位、檔案權限／保留期限；讓行前交付包含實際原件。需要先決定安全儲存方式與可存證件範圍。
2. **主動期限提醒與交接**：按責任人彙整、每日到期摘要、提醒送達狀態；明確管理提醒授權、頻率與取消，避免誤催已完成項目。
3. **改退與旅中工作單**：供應商條件、費用試算／人工核對、客人決定、實際取消／退款進度與緊急聯絡。
4. **依媽媽實際產品補專門流程**：先記錄常見工作，再決定多日行程、團體配額、保險／簽證等優先順序。
