# Workspace reliability and design verification

Date: 2026-10-03. Baseline: `844cec3`. Scope: existing shared Mom/admin FastAPI application, without connecting OpenClaw or deploying a public tunnel. All mutation/browser evidence uses synthetic data on disposable databases.

Implemented: per-booking verified e-tickets/vouchers; travel/booking-revision verification stamps and explicit legacy recheck; current-proof filtering plus blocker recomputation at export/delivery; atomic verified-actor case audit and travel-edit status reset; shared lifecycle recommendations and urgent task precedence; actual ASGI request-byte limit behind authentication; UTF-8 token comparison; Docker context exclusion. The established UI is shorter, deadlines precede shortcuts, and secondary sales work is collapsed. Sheet input/replies get discard protection; pending saves lock editing/navigation; failed committed refresh leaves read-only contents and retry navigation. Independent loaders, latest-response ownership, selection locks, manual deadline templates and modal-scoped focus complete the change. English architecture and generated Traditional Chinese guide describe actual behavior.

Validation:

- Python 3.12 and 3.11 regression suites: **171 passed** each, run sequentially because the fixture uses one fixed temporary database.
- Headless Chrome: **41 checks passed**, no JavaScript errors. Repeatable runner: `scripts/verify_mom_workspace.py --chrome /path/to/chrome`, requiring Playwright. It launches its own ephemeral loopback port/database and removes them; screenshots contain synthetic customers only.
- Browser scenarios cover close/Escape/back/replacement Cancel, explicit discard, slow-save inertness, dirty/clean/failed case association, already-authorized pending discard, stale completion, required blank deadline templates, missing-case manual-entry focus, lifecycle/back errors, successful mutation followed by failed refresh with no duplicate retry write, keyboard details, direct missing-date editing, urgent-record focus, catalogue/preferences degradation and recovery, login expiry, and 390/768/1360px extra-large targets/overflow.
- Docker scratch `COPY` context built and exported: `.env`/data/databases/key files/virtual environment/VCS absent; app/static/recipes/pyproject present. Disposable container and image removed. This verifies context isolation, not a new full runtime image deployment.
- Both JavaScript syntax checks, generated-guide drift, **23 local skill checks**, and diff whitespace pass. No travel legal/contract rules were changed. Official Docker context and ASGI request documentation were checked for the implementation; links are in the architecture doc.

Independent review used read-only design and implementation checkpoints. Backend used Claude because security, transactional state and multi-file API behavior meet the High criteria; every usage gate allowed the call (`seven_day=1%`). Final **APPROVE**. Frontend always used Cursor with `gpt-5.6-sol-xhigh`, selected from the live installed model list. Its third/final checkpoint was **REVISE**: freeze committed forms after failed refresh, scope a browser locator, and narrow guide wording to sheet forms. All were corrected and regression checked. The three-round cap was respected, so there is no fourth independent approval for those final small fixes. No frontend blocker/major remains known.

Inherited conservative limits retained: blank versus null origin can cause an extra reverification; mid-upload disconnect stops side effects but may produce outer-middleware log noise. Lifecycle-specific close/reopen, labelled historical audit export, attachment storage, passenger manifests, external reminders and specialist/group/change-ticketing workflows remain future scope. Obsolete delivered packs remain internally stored but cannot be re-exported for customer use. Real Cloudflare IdP/MFA/tunnel and Mom's usability require actual deployment/user testing; these were not claimed.

Ignored local evidence: `data/hardening-review/browser/results.json`, desktop/mobile/tablet screenshots, reviewer JSON and `docker-context.json`. See [architecture](DEVELOPER_ARCHITECTURE.md), [user guide source](USER_GUIDE_ZH_TW_DRAFT.md) and [design QA](../design/qa.md).
